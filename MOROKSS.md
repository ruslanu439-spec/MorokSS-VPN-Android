# MorokSS VPN для Android

Это форк официального Shadowsocks Android. В него встроен транспорт MorokSS.
Исходник приложения взят из
[shadowsocks/shadowsocks-android](https://github.com/shadowsocks/shadowsocks-android),
а исходник транспорта подключён в `third_party/morokss`.

## Как подключиться

1. Открой приложение.
2. Нажми `+`.
3. Выбери «Вставить JSON MorokSS».
4. Вставь весь JSON, который выдал сервер.
5. Сохрани профиль и включи VPN.

## Диагностика ограничения потока

В боковом меню есть экран «Диагностика сети». Отключи VPN, запусти проверку и
сохрани приватный JSON. Клиент отдельно сравнит передачу 96 КиБ в одном TLS-потоке
с тем же объёмом через восемь новых соединений по 12 КиБ, причём отдельно для
загрузки и выгрузки.

Если длинные потоки обрываются, а короткие проходят, отчёт помечается как
`likely_bidirectional_per_flow_limit` или `likely_directional_per_flow_limit`.
Если не проходят и короткие соединения, вероятнее фильтрация endpoint/подсети или
общий лимит, а не ограничение одного потока. Это диагностический вывод, а не
гарантия обхода.

По умолчанию JSON не содержит endpoint, TLS hostname, пароль Shadowsocks и секрет
MorokSS. Уникальные `trace_id` позволяют сопоставить клиентские попытки с журналом
сервера без записи IP клиента.

JSON можно также открыть как файл или скопировать в буфер и выбрать обычный импорт.
Приложение само достанет настройки Shadowsocks, endpoint, TLS hostname и секрет.

## Burst upload

Для сети, в которой длинная исходящая передача зависает, а новые короткие потоки
проходят, профиль может принудительно включить Burst-режим:

```json
{
  "burst_upload": true,
  "burst_chunk": 4096,
  "burst_parallel": 2
}
```

Один управляющий TLS-поток постоянно принимает загрузку с сервера. Исходящий TCP
разбивается на короткие аутентифицированные TLS-соединения. Каждый блок имеет номер,
подтверждение и до трёх попыток; сервер собирает блоки по порядку в один исходный
TCP-поток. По умолчанию используются блоки 4 КиБ и два параллельных соединения.
Допустимый диапазон — 1–8 КиБ и 1–8 соединений.

Режим экспериментальный и применяется только к исходящей стороне TCP. UDP пока
использует обычный транспорт. Результат зависит от конкретной сети: если оператор
начнёт ограничивать частоту новых TLS-соединений или заблокирует IP целиком, одного
Burst-режима будет недостаточно.

## Что происходит внутри

`ss-local` принимает трафик Android как обычный Shadowsocks-клиент. Но вместо
прямого соединения с сервером он отправляет TCP и UDP на локальный MorokSS.
MorokSS заворачивает поток в выбранный TLS-профиль и транспорт, а затем идёт на
один из endpoint сервера.

При автовыборе обычного TCP-транспорта клиент проверяет передачу 96 КиБ в обе
стороны. Так он замечает сеть, где TLS-handshake проходит, а поток потом зависает.
Принудительный Burst-режим пропускает эту длинную исходящую проверку. Рабочая
связка endpoint, SNI, TLS-профиля и транспорта запоминается отдельно для мобильной
сети и Wi-Fi.

Свой список запасных SNI можно добавить в JSON:

```json
{
  "cover_sni": ["example-one.com", "example-two.com"]
}
```

Это необязательное поле. Один и тот же список не работает у всех операторов.
Даже с запасным SNI приложение продолжает проверять настоящий сертификат
MorokSS-сервера.

Исходящие сокеты MorokSS передаются в Android `VpnService.protect()`. Поэтому
они не попадают обратно в TUN и VPN не зацикливается. Секрет передаётся процессу
через переменную окружения и не виден в командной строке.

## Сборка

Нужны JDK 17+, Android SDK 36, NDK 27, Rust и Go 1.24+.

```powershell
git clone --recurse-submodules https://github.com/ruslanu439-spec/MorokSS-VPN-Android.git
cd MorokSS-VPN-Android
./scripts/build-morokss.ps1 arm64-v8a
./gradlew.bat -PTARGET_ABI=arm64 :mobile:assembleDebug
```

На Linux вместо PowerShell используй `./scripts/build-morokss.sh arm64-v8a` и
`./gradlew`.

## Ограничения

Один IP всё равно можно заблокировать целиком. Автовыбор помогает только пока
в конфиге есть хотя бы один доступный endpoint и сервер нормально отвечает.
Ошибку сети нельзя со стопроцентной точностью отличить от блокировки.

Сейчас готова ARM64-сборка. Это большинство современных Android-телефонов.
Перед стабильным релизом ещё нужны тесты на реальных сетях разных операторов.
